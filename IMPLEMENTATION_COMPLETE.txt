│  ├─ ip_address (INET)
│  ├─ user_agent (TEXT)
│  ├─ reason (TEXT)
│  └─ metadata (JSONB)
├─ Constraints: 1
│  └─ admin_audit_not_empty CHECK
└─ Status: ✅ Immutable (no UPDATE/DELETE possible)

INDEXES: 6 (optimized query patterns)
├─ idx_admin_audit_by_admin (admin_user_id, created_at)
├─ idx_admin_audit_by_table (table_name, created_at)

├─ idx_admin_audit_action (action, created_at)
├─ idx_admin_audit_record (table_name, row_id, created_at)
└─ idx_admin_audit_admin_email (admin_email, created_at)

PERMISSIONS:

└─ admin users: SELECT (via RLS policy)

HOW IT WORKS (AUTOMATIC)
================================================================================

Timeline:
1. Admin modifies feature_flags table
   ↓
2. PostgreSQL trigger fires immediately
   ↓
3. Trigger function calls log_admin_access()
   ↓
4. Function inserts audit entry with:
   - Who: admin_user_id, admin_email
   - When: created_at timestamp
   - What: action (UPDATE)
   - Where: table_name (feature_flags)
   - How: before_values & after_values (full JSONB)
   ↓
5. RLS policy prevents any UPDATE/DELETE of audit entry
   ↓
6. Entry is permanently immutable and auditable

Result: Automatic, complete, tamperproof audit trail

SUPPORT & TROUBLESHOOTING
================================================================================

Q: Migration won't apply?
A: Check for syntax errors, verify PostgreSQL version compatibility,
   review Supabase logs for detailed error messages.

Q: Audit log is empty after changes?
A: Verify you're logged in as admin (role='admin'), check triggers exist,
   see troubleshooting section in README_ADMIN_AUDIT_LOG.md

Q: Getting permission denied errors?
A: Only admins can SELECT. Verify your role in instructors table.
   Non-admins will see 0 rows (RLS blocks access).

Q: Want to delete an audit entry by mistake?
A: By design, no one can delete entries. For critical compliance
   violations, contact Supabase support only.

See ADMIN_AUDIT_LOG_IMPLEMENTATION_SUMMARY.md for more Q&A.
